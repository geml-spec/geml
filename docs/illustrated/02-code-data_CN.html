GEML 块图解 · code 与 data

这一页是 code 和 data。两者放一起，因为它们是一对镜像：code 装处理器永不解释的文本，data 装必须解析通过的值；两者共用一套 src= 路由语法，却对「解析不到」给出相反的轻重。每条规则标出处，右边是 geml check、geml get 和 --to html 的实测输出。

两者共用
1一套路由语法：src=<path>[#L<start>[-<end>]]，1 起始、闭区间；相对文档解析，给了 --root 也可相对根；http(s) 由渲染器取，其它 scheme 拒绝。§3.3 · §9.4规范已定
2同一个属性两种轻重：code 的 src 解析不到是 warning（块描述的是某处的一段代码，源码不在手边文档仍成立）；data 的 src 解析不到是 error（值就是文档承诺的内容）。范围漂移两者都是 error。§3.3 · §3.2规范已定
3code 与 data 都不许 src 与正文同在（code-src-and-body、data-src-and-body error）。code 的路由不看后缀，data 的必须是 .json/.jsonl。§3.3 · §3.2 · A.5规范已定
code
4raw 体，lang= 只是标签；正文永不执行。渲染为 <pre><code class="language-xx">。§3 · §9.1规范已定
5src=<path>[#L<s>[-<e>]] 引用源码。src 与正文同在 error；范围漂移 error；解析不到 warning（图仍有效）；非法 scheme error。§3.3 · A.5规范已定
data
6值树（JSON 值域）。json 默认，jsonl 每行一值、空行忽略。解析失败是 data-parse error，指出行号。§3.2 · A.5规范已定
7yaml/toml 是保留名：无引擎时正文保留、给 warning、不猜。未知 format 同样降级。csv 不是 data 格式。§3.2规范已定
8src= 与正文互斥 error；文件须 .json/.jsonl；schema= 保留，形状不对 error，不做校验。§3.2 · A.5规范已定

code：原文，或者一段源码的路由

正文是文本，永不执行（§9.1）。可以不抄代码，用 src= 指向文件和行号，drift 会被抓住。

data：被验证的值树

GEP-0005 加进来的。code 装的是不许解释的文本，data 装的是必须解析通过的值。
