GEML 块图解 · table 与 view

table 是规范里规则最多的类型：两种体、一个模型、一门封闭的算术、一行汇总。GEP-0012 提出的 view 把「从另一张表选、算、聚合」搬出来，并打算把「借别的表的行」从 table 里拿走。这一页先把 table 今天的每条规则实测一遍，再把 view 的草案画出来，标清哪些是规范、哪些是草案、哪里两者冲突。

规则出处状态
table
1两种可互换的体、一个模型：可视管道表（默认），或 format=csv/tsv 数据体加 header=。模型是列模型，单元格值是字符串、数字或布尔，日期是 ISO-8601 文本。§6规范已定
2delim= 只对数据体有效，必须恰一个字符；tab 写 format=tsv。两字符是 bad-table-delimiter error 并回退自然分隔符；无 format 时是 ignored-table-delimiter warning。未知 format warning，按可视网格解析。§6 · A.3规范已定
3src= 三种目标：csv/tsv 文件（相对路径或 http(s)）、#id 本文档表、doc.geml#id。解析不到 error；目标不是表 error；src 与正文同在 error。只有 src 文本进 .gemlhistory 哈希，内容不进。§6 · A.3规范已定
4compute=：Name = expr 用 ; 分隔，算术 + - * / ( ) 和一元负；按表头名（含空格用单引号）或字母列引用；可引用前面算出的列，无环。空或非数单元格按 0 并 compute-non-numeric-cell warning；除零得无值、显示 - 并 compute-not-a-number warning。计算列追加在数据列后，不写进正文。§6 · A.3规范已定
5summary=：一行汇总，Cell = value；值是字面量标签或聚合表达式，聚合只有 sum avg min max count，是唯一跨行的构造；列引用必须被聚合；未指定列空白；未知列 error。§6 · A.3规范已定
6[printf] 显示格式绑定在公式左侧名字上，只影响显示；判定是左侧最后一个含 % 的 […]，所以列名本身可以带方括号。§6规范已定
7明确排除：单元格与区间寻址、相对行引用、条件、跨表 remote()、lookup、任何嵌入程序。表是文档特性，不是电子表格引擎。§6规范已定
8外部数据渲染时到达，所以 compute 和图表引用的列名在渲染时校验，不在构建时。§6 · §9.4规范已定
9渲染：figure.table-figure > table.geml-table，计算列 td.computed，数字单元格带 data-sort，汇总行在 tfoot，caption 在 figcaption。--to html实测
10坐标：#fy[2] 一行（1 起始，表头不算行）、#fy[2]["Q1"] 一格、#fy["Q1"] 一列、#fy[summary]["FY"] 汇总格。整数是行、引号是列、裸词是保留行名。list 不枚举坐标。GEP-0011GEP 草案
11借表：table {src=#fy compute=…} 今天合法，且能对借来的行再算（1.9.3 修复）。GEP-0012 要把 src= 指向块的 table 改成 error 并指向 view：块目标是别人的输出，借它的 table 就不再是「事实」。§6 ↔ GEP-0012GEP 草案
view（GEP-0012，草案；今天未注册，是 unknown-block-type warning）
12view 无正文，必须 src=，目标同 §6 三种；正文与 src 同在 error。GEP-0012GEP 草案
13选择：where=（比较、and/or/not、数字或单引号字面量）、order=（asc/desc，稳定排序）、limit=、select=（只取名字，含 = 报错指向 compute）。GEP-0012GEP 草案
14派生与聚合：compute=/summary= 语法不变，搬到 view；by= 分组键，aggregate="Name = fn(col)"；by= 无 aggregate 即 distinct。GEP-0012GEP 草案
15求值顺序是 SQL 的逻辑顺序：src → compute 行级 → where → compute 聚合 → by/aggregate → order → limit → select → summary。compute 两遍所以 where 能用刚算的列；select 晚跑所以 order 能用未显示的列；summary 最后，是对显示行的报告。GEP-0012GEP 草案
16一种表达式语言：单引号在列位置是列名、在值位置是字面量。where= 里未知列 error；全无数值的列比数字 error；单个非数单元格不匹配、无诊断。没有正则、like、函数。GEP-0012GEP 草案
17view 看到源的元组和计算列，看不到源的 summary 行；同名 compute= 遮蔽源列合法但 shadowed-source-column warning。过滤分组是再来一个 view，不是 HAVING。GEP-0012GEP 草案
18草案缺口：0012 正文没有一处提到图表。§7.1 的 data= 今天只接受 table 或记录数组 data 块；compute 搬走后，画计算列的图（如 y=FY）就没有合法数据源。需要补：data= 接受 view，贡献其输出关系为表模型；rows=all|summary 对 view 自己的 summary 行生效；诊断措辞与 conformance suite 各加一条。GEP-0012 ↔ §7.1草案缺口
