GEML Blocks Illustrated · table and view

table is the type with the most rules in the specification: two bodies, one model, a closed arithmetic, one summary row. GEP-0012's proposed view moves "select, derive and aggregate from another table" out of it, and intends to take "borrowing another table's rows" away from table. This page first measures every rule table has today, then draws the view draft, marking what is specified, what is draft, and where the two collide.

1Two interchangeable bodies, one model: a visual pipe grid (the default), or a format=csv/tsv data body with header=. The model is a column model; a cell is a string, number or boolean; dates are ISO-8601 text.§6Specified
2delim= applies only to a data body and must be exactly one character; a tab is spelled format=tsv. Two characters is a bad-table-delimiter error that falls back to the natural delimiter; with no format it is an ignored-table-delimiter warning. An unknown format is a warning, parsed as a visual grid.§6 · A.3Specified
3src= takes three targets: a csv/tsv file (relative path or http(s)), #id of a table in this document, doc.geml#id. Unresolvable: error; not a table: error; src with a body: error. Only the src text enters the .gemlhistory hash, never the contents.§6 · A.3Specified
4compute=: Name = expr entries separated by ;, arithmetic + - * / ( ) and unary minus; columns by header name (single-quoted when it has a space) or letter; an earlier computed column may be referenced, acyclically. An empty or non-numeric cell counts as 0 with a compute-non-numeric-cell warning; division by zero yields no value, displays -, and warns compute-not-a-number. Computed columns are appended after the data columns and never written into the body.§6 · A.3Specified
5summary=: one foot row of Cell = value entries; a value is a literal label or an aggregate expression; the aggregates sum avg min max count are the only construct that crosses rows; every column reference must be reduced by an aggregate; unspecified columns are blank; an unknown column is an error.§6 · A.3Specified
6A [printf] display format binds to the name on the left of a formula and affects display only; it is the last […] group of the left side that contains a %, so a column name may itself be bracketed.§6Specified
7Excluded by design: cell and range addressing, relative-row references, conditionals, cross-table remote(), lookup, any embedded program. A table is a document feature, not a spreadsheet engine.§6Specified
8External data arrives at render time, so the column names used by compute and by a chart are validated then, not at build time.§6 · §9.4Specified
9Rendering: figure.table-figure > table.geml-table; computed cells are td.computed, numeric cells carry data-sort, the summary row sits in tfoot, the caption in figcaption.--to htmlObserved
10Coordinates: #fy[2] a row (1-based; the header is not a row), #fy[2]["Q1"] a cell, #fy["Q1"] a column, #fy[summary]["FY"] the summary cell. An integer is a row, a quoted string a column, a bare word a reserved row name. list does not enumerate coordinates.GEP-0011GEP draft
11Borrowing: table {src=#fy compute=…} is legal today, and computes over the borrowed rows (fixed in 1.9.3). GEP-0012 would make a table whose src= names a block an error pointing at view: a block target is someone else's output, and a table that borrows it is no longer "facts".§6 ↔ GEP-0012GEP draft
view (GEP-0012, draft; unregistered today, so an unknown-block-type warning)
12view has no body and a required src=, with §6's three targets; a body alongside src= is an error.GEP-0012GEP draft
13Selection: where= (comparisons, and/or/not, numbers or single-quoted literals), order= (asc/desc, stable), limit=, select= (names only; an = inside it is an error pointing at compute).GEP-0012GEP draft
14Derivation and aggregation: compute=/summary= keep their grammar and move to view; by= names grouping keys, aggregate="Name = fn(col)" the group columns; by= without aggregate is the distinct set.GEP-0012GEP draft
15Evaluation order is SQL's logical order: src → per-row compute → where → aggregate compute → by/aggregate → order → limit → select → summary. Compute runs in two passes so where may use a column defined in the same block; select runs late so order may sort on an unshown column; summary runs last, as a report over the rows shown.GEP-0012GEP draft
16One expression language: a single-quoted run is a column name in column position and a literal in value position. An unknown column in where= is an error; a text-only column compared against a number is an error; a single non-numeric cell simply does not match, with no diagnostic. No regexes, no like, no functions.GEP-0012GEP draft
17A view sees the source's tuples plus its computed columns, never its summary row; a compute= shadowing a source column is legal with a shadowed-source-column warning. Filtering groups is the next view, not a HAVING.GEP-0012GEP draft
18Draft gap: GEP-0012 never mentions charts. §7.1's data= accepts only a table or a record-array data block today; once compute moves out of table, a chart over a computed column (y=FY) has no legal source. Needed: data= admits a view, contributing its output relation as the table model; rows=all|summary acts on the view's own summary row; one diagnostic wording and one conformance case each.GEP-0012 ↔ §7.1Draft gap
