# geml-translator profile v1 —— `embed` 上的语言轴

*[English](geml-translator-profile.md) | 中文*

- 状态：**草案**，绑定 [GEP-0010](../../proposals/0010-language-projections.md)（草案）。
  它先在参考实现里注册，好让今天写出的译文文档能校验干净；下面每一条语义都属于
  那份提案，随它变动。
- 性质：**应用层 profile，不属于 GEML 标准。** §8.6.1 把属性键列为词汇表可以放行
  的东西之一，所以语言轴不需要改规范：一个键，挂在一种块上。从未听说过这个
  profile 的处理器完全合规——它读到同样的块、同样的顺序，只是不翻译。

## 0. 一段话说清

一份译文是源文档沿**语言轴**的投影，和 `.md` 沿格式轴的投影是同一个形状
（[GEP-0006](../../proposals/0006-declared-projections.md)）：译文文件里除了
`embed` 什么都没有，每个 embed 指向源的一个单元，并说它要哪种语言。声明了
`profile = "geml-translator/v1"` 的文档，可以在这些 embed 上、以及在
`=== meta` 上（作为文档默认）写 `translate-to`，而 `geml check` 不会把它报成
`unknown-attribute`。因为 id、块顺序、每一个非散文字节都留在源里、只有一个家，
译文不可能与它翻译的东西漂移——它里面没有可漂移的东西。

## 1. 声明 profile

```geml
  === meta
  title        = "发布"
  profile      = "geml-translator/v1"
  source       = "PUBLISHING.geml"
  translate-to = "zh-cn"
  ===
  === embed {src=PUBLISHING.geml#topology}
  ===
  === embed {src=PUBLISHING.geml#prereq translate-to=none}
  ===
```

`profile` 是空格分隔的列表，所以一份文档可以同时声明别的词汇表。放行只给
**名字**：它不改变正文模式，同一段字节无论 profile 是否被认识，都解析成同一个
文档模型（§8.6 规则 4）。

## 2. 一个键，两个位置

| 写在哪 | 意思 |
|---|---|
| `=== meta` | 文档默认：所有没写自己值的 `embed` 都继承它 |
| `embed` 上 | 覆盖该块的默认 |
| `embed` 上，值为 `none` | 这一块留下不译——照样投影，但不翻译 |

值是语言标签（`zh`、`zh-cn`、`de`）。规范不约束标签的取值集合，理由和 §3 不约束
`code` 块上 `lang=` 的取值一样：那套集合属于世界，不属于这个格式。

`none` 值得有自己的拼法，因为**「不写」本身已经有含义**：没有 `translate-to` 的
embed 继承文档默认，所以在一份设了默认的文档里，否则就没有办法说「这一个不要」。

## 3. 为什么是 `translate-to` 而不是 `lang`

`code {lang=sh}` 命名的是**编程**语言，是关于正文*已经是什么*的陈述。这里若用一个
键去命名自然语言，那是关于要对正文*做什么*的**指令**。两个取值空间、两种词性，
挤在一个键上——而这个格式的前提是一个名字只有一个意思。`translate-to` 是个动词，
读不成另外两个。

## 4. 前提：embed 必须铺满源

这个 profile 让 embed 拼贴成为翻译的单位，所以一份源文档能被翻译的程度，恰好等于
它**可寻址**的程度。embed 必须从源的 `meta` 结束一直覆盖到文件尾。落在任何可寻址
单元之外的散文——比如第一个标题之前的那一段——不会被投影，因此也不会被翻译，而且
没人报告，因为没人被要求。

这是可检查的：`geml list` 给每个单元打印行范围，缝隙是算术。GEP-0010 拿规范自己
量过——十六个 `##` 节零缝隙铺满全篇，52 行的译文投影出 1349 行 Markdown，与源逐
字节相同。

没人能寻址的散文，也没人能嵌入、翻译或按块编辑它；§3 的 `text` 块就是它的家。

## 5. 翻译器必须保留什么

规范说不了该怎么翻译，但能说什么必须活下来。以下是对任何执行 `translate-to` 的
处理器的要求：

- **verbatim 行内原子。** code span 和行内数学要*绕着*译，不能穿过去——§4 对
  `{{key}}` 插值早已是同一条规则。
- **每个引用及其目标。** 标签可以译，目标不可以。`[[#id]]`、`[text](#id)`、
  `[^fn]` 和链接 href 原样保留，否则 §8.2(5) 会把译文变成一个构建错误。
- **每个 id、class 和属性键**，以及那些*命名*事物而非*陈述*事物的属性值：
  `format=`、`src=`、`translate-to=`。
- **块结构**：同样的块、同样的顺序、同样的 id。
- **不许部分输出。** 失败、超时、引擎不可用时，该块留在源语言。半句译文比不译更糟。

**整块一次翻译，不要逐个行内片段送。** 把不可动的 span 换成占位符，既保住原子不
变，又仍然送出完整的句子；占位符必须在目标语言里惰性、允许被翻译器移动、并且回来
时必须**校验**——每个恰好出现一次——不满足就整块回退源语言。逐段送出去在实测上明显
更差：GEP-0010 记录了一份文档 133 次调用，其中 57 次短于 25 字符，35% 的散文块被
拆成碎片，拼回来时标点全角半角对不上。

## 6. 词表钉住引擎每次都会重新决定的词

结构不会漂，词汇会。翻译器按块调用、不记前事，一个术语出现八次就被决定八次。译文
可以为这类术语带一份定下的译法：

```geml
  === meta
  profile      = "geml-translator/v1"
  translate-to = "zh-cn"
  glossary     = "#terms"
  ===

  === table {#terms hidden}
  | term | zh-cn |
  |---|---|
  | Single Source of Truth | 单一事实来源 |
  ===
```

三条规范里已有的规则完成了全部工作：`hidden`（§4）是「进模型、不显示」的结构化
内容的标志；`meta` 的值装不了表，所以那个键是一个引用；而表就是一个普通块。词表
由投影层应用，不是拿去问引擎——而且它住在**译文**里，因为定下的译法是译文的属性，
不是源的属性。

## 7. 这个 profile 不放行什么

- **`translator=`** —— 保留，不发货。只有一个引擎可用时，一个在引擎之间做选择的
  键会「解析、什么都不做、看着像被支持」。它留给有第二个引擎的时候。至于处理器
  从哪里拿到翻译器——浏览器内置、操作系统服务、某个工具、shell 出去的 CLI——是实现
  定义的，一个都拿不到仍然合规。
- **`except=`** —— 已撤。早期草案里有一个「在节级 embed 内部要跳过的 id 列表」；
  文档默认消掉了这个需求：一个单元一个 embed 的拼贴几乎不费笔墨，于是「例外」就是
  在那一个 embed 上写 `translate-to=none`。同一意图的第二种拼法还会需要它自己的
  核心诊断——那种列表里的拼写错误只会引来 `unknown attribute`，永远不会引来一条
  未解析引用，而这是一个以消除沉默为目的的词汇表。
- **`lang=`** —— 见 §3。它是 `code` 的键，说的是另一件事。

## 8. 诊断

这个 profile **没有自己的诊断**。它能出的错，核心都已经报了：

| 情形 | 得到什么 |
|---|---|
| 写了 `translate-to` 但没声明 profile | `unknown-attribute` **warning**（附录 A） |
| `src=` 指向不存在的东西 | `unresolved-reference` / `unresolvable-document` **error** |
| 译文里某个引用的目标已不可解析 | 同上，在译文里报 |

认识这个键但翻不了的处理器，不得假装翻过了。参考实现的 `--to md` 和 `--to html`
不带翻译器，所以它们输出源文并在 stderr 说明：`translate-to=… was not applied:
this export has no translator`。

## 9. 版本与范围

`v1` 就是一个键。如果提案原样通过，这份文档就成为它对该词汇表的规范性陈述；如果
提案改了这个键的名字或它能出现的位置，profile 名进到 `v2`，而这个文件继续描述
`v1`，供已经照它写好的文档使用。这里没有任何东西改变文档模型，所以 `v2` 永远不会
让一份已有文档解析出不同的结果——只会翻译出不同的结果。
